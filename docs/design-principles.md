# C-Relations デザイン原則（1枚）

このプロダクトの見た目・操作を決めるときの判断基準。**迷ったらこの順で優先する。**
新しいUIを足す前にここを読み、逸脱するなら理由を書く。

---

## 0. 最上位の3原則（すべてに優先）

1. **引き算 > 足し算** — 機能を足すより、要らないものを隠す/消す。初回に見えるコントロールは最小限に。
2. **まず絞る → それから見る** — 4,000件を一度に見せない。担当・工区・CPで絞った"自分のスライス"が主役。
3. **一目で分かる** — 今何を見ているか・何が起きたかを、言語（バナー）と動き（アニメ）で即座に伝える。

> 判断に迷ったら「これはユーザーの認知負荷を**下げる**か？」で決める。下げないなら足さない。

---

## 1. 情報アーキテクチャ（何を出す/隠す）

- **常時見せる**：絞り込みの主役（組込みビュー・工種/状態/担当フィルタ・WBSツリー・保存ビュー）、＋タスク、Undo/Redo、ビュー切替。
- **折り畳む（詳細設定 ▾）**：私は誰・稼働カレンダー・統計・凡例・詳細フィルタなど"普段触らない"もの。
- **メニューに集約（操作 ▾ / データ ▾）**：二次操作（整列・プロジェクト管理・入出力・デモ）。
- 目安：**初回に見えるコントロールはヘッダ7・左パネル4セクション以内**。これを超えたら折り畳みを検討。

## 2. カラー

| 用途 | トークン | 値 |
|---|---|---|
| アクセント（主行動・選択・リンク） | `--accent` | `#0071e3` |
| 文字（主） | `--ink` | `#1d1d1f` |
| 文字（副） | `--muted` | `#6e6e73` |
| ラベル（淡） | `--faint` | `#86868b` |
| 背景 | `--bg` | `#f5f5f7` |
| ヘアライン境界 | `--panel-border` | `#e7e7ec` |
| コントロール地 | `--ctl-bg` | `#f1f1f4` |
| 工種 E/P/C/OTHER | `--disc-*` | `#2563eb`/`#d97706`/`#059669`/`#6b7280` |
| クリティカル | — | `#dc2626`（赤は"注意/CP"専用。多用しない） |
| 通電エフェクト | — | `#22d3ee`（接続の一瞬だけ） |

- **原則**：地は白〜淡グレー、文字は黒に寄せる、**色は意味のある所だけ**（アクセント青・工種・CP赤）。
- **禁止**：装飾目的のベタ塗り、彩度の高い背景、意味のない色分け。
- ⚠️ **色だけに頼らない**（アクセシビリティ）：工種などは色＋文字/形も併記する。

## 3. 余白・角丸・影・タイポ

- **角丸**：小要素 `--radius-sm`(7px)、カード/パネル `--radius`(10px)、ピル/チップは `999px`。
- **影**：`--shadow-sm`（浮くボタン）/`--shadow-md`（MiniMap等）/`--shadow-lg`（ドロップダウン/ポップオーバー）。**線で囲むより影で浮かせる**。
- **境界**：ヘアライン1px。強調は影で。濃い/太い枠は避ける。
- **タイポ**：本文13px、見出しは字間 `-0.01〜-0.02em`。セクションラベルは10.5px・uppercase・`--faint`。
- **余白リズム**：詰めすぎない。Apple的に"呼吸"を残す（行間・パディングを削りすぎない）。

## 4. コンポーネントの型（迷ったら既存に合わせる）

- **ボタン**：既定＝`--ctl-bg`地・無枠・状態レイヤ。主行動＝`.primary`（青）。トグルON＝`.on`（青トーン＋内側リング）。
- **チップ**：pill形・白地・ON で `--accent-weak`。
- **ドロップダウン/ポップオーバー**：白・角丸11〜14px・`--shadow-lg`。**ヘッダ由来は z-index 90 以上**（他の浮遊UIに潜り込ませない）。
- **セグメントコントロール**：ビュー切替はiOS風ピル（`--ctl-bg`地・アクティブ白＋影）。
- **状態バナー**：`--accent-weak`地・ドット＋言語化＋件数＋ワンクリック解除。

## 5. インタラクション & アニメーション

- **フィードバックは必ず返す**：作成/接続/保存/エラーはトースト・バッジ・バナーで即応。
- **状態変化は動きで橋渡し**：フィルタ変更→**結果へ自動フィット**、新規ノード→**フェードイン**(nodeIn 0.22s)、接続→**通電エフェクト**(約0.95s)。
- **控えめ・短く**：アニメは 0.12〜0.5s。装飾のためだけの動きは入れない（"意味のある動き"だけ）。
- **全操作にマウス以外の経路**：主要操作はキーボード（G/T/Y・Cmd+K・N/Tab/H・Esc）でも到達可能に。
- **破壊的操作は確認**：削除は confirm、Undo可能を明示。

## 6. パフォーマンスは体験の一部

- 4,000件でも仮想化・表示パイプライン（フィルタ/折り畳み/近傍）で常時数百に抑える。
- 重い処理（全体整列）は Worker・非同期。UIをブロックしない。

---

## この原則の使い方

- **新UI追加時**：0→1→2…の順にチェック。特に「常時見せる必要があるか？（隠せないか）」を最初に問う。
- **色/余白/影で迷ったら**：§2〜3のトークンを使う。新しい値を足す前に既存で足りないか確認。
- **逸脱する場合**：理由をコミット/PRに書く（例：撤退可能性のためReact Flow依存は adapters に隔離、等）。
