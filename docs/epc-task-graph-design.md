# C-Relations — EPC タスク依存関係グラフエディタ 設計書 v2.0

EPCプロジェクト（設計 E / 調達 P / 施工 C）の**タスク依存関係を、ノードグラフ・表・ガントの
3ビューで直感的に作成・編集・可視化する**Webアプリ。クリティカルパスを第一級機能とし、
4,000タスク規模を「一度に描かず、絞って見る」設計で扱う。

> 本書は最終形の設計を一貫した計画として記述する。見た目・操作の判断基準は
> [`design-principles.md`](./design-principles.md) を参照（新UI追加時は必読）。

---

## 0. プロダクト原則

判断に迷ったらこの順で優先する。

1. **編集体験が存在意義** — 依存関係を直感的に整理できること。表でセルを埋める作業ツールにしない。
2. **引き算 > 足し算** — 機能を足すより隠す/消す。初回に見えるコントロールは最小限。
3. **まず絞る → それから見る** — 4,000件を一度に見せない。担当・工区・CPで絞った"自分のスライス"が主役。
4. **一目で分かる** — 今何を見ているか・何が起きたかを、言語（バナー）と動き（アニメ）で即座に伝える。
5. **結果が動いたら即フィードバック** — 編集で完了日・CP・日付が変われば、その場で反映する。

### 用語（UI文言もこれに統一）

| 用語 | 意味 |
|---|---|
| **タスク** | 作業の1単位（ノード）。E/P/C/OTHER の工種を持つ。 |
| **依存** | タスク間の順序関係（有向エッジ）。先行→後続。タイプ FS/SS/FF/SF ＋ ラグ。 |
| **先行/後続** | pred / succ。「親/子」という曖昧語は使わない。 |
| **WBS** | `1.2.3` 形式の階層コード。折り畳み・分担・ツリーナビの単位。 |
| **担当** | 部署名（班/セクション単位）。個人名ではない。「自分」＝自部署。 |
| **クリティカルパス（CP）** | 遅れると全体が遅れる背骨。TF ≤ 0 のタスク連鎖。 |

### 非スコープ

多言語（日本語UIのみ）。`.mpp` バイナリ直接読み書き（MSPDI XMLで代替）。リアルタイム共同編集
（発動条件を満たすまで作らない、§12）。

## 1. 想定ユーザーと主要ユースケース

- **各工種の担当者（部署）** — 自分の担当タスクと、その前後の受け渡し（他部署とのインターフェース）を
  確認・編集する。**これが日常の主動線。**
- **プロジェクトマネージャ** — クリティカルパスと全体マップを把握し、対外説明にガントを使う。
- **計画部門** — MS Project との往復（MSPDI）で既存工程表を取り込む。

### コア操作フロー

**初回**は「ようこそ」で担当（部署）を尋ね、選ぶと**自分のスライス（担当＋前後1世代）で開く**——最初から
"まず絞る" の入口に立てる（初回のみ・localStorage 記憶）。以降は既定ビュー★や組込みビューで同じ入口へ。

1. **絞る** — 「自分のタスク」（担当＋前後1世代）／「CPのみ」／WBSツリーで工区を選ぶ。
2. **見る** — グラフ（依存関係）／テーブル（一覧・並べ替え）／ガント（時間軸）を切り替える。
3. **編集** — タスクの作成（`N`）・後続の連続作成（`Tab`）・依存の接続/切断（つなぐモード or ドラッグ）・
   インライン編集。すべて Undo 可能。
4. **確認** — 完了日サマリ・CP・TF が即時更新。保存は自動（差分・デバウンス）。

## 3. UX・インタラクション設計（本ツールの核）

### 3.1 操作系

- **マウス/トラックパッド**：空白ダブルクリックで作成、ハンドルからドラッグで接続、ノードドラッグで移動、
  ホイールズーム。トラックパッドでのドラッグ接続が難しい場合のため**「つなぐモード」**（§3.6）を用意。
- **キーボード（全操作にマウス不要の経路）**：
  `N`=新規／`Tab`=後続を連続作成／`Enter`=名前編集／`H`=関係ハイライト／`Delete`=削除／
  `G`/`T`/`Y`=ビュー切替／`Cmd/Ctrl+K`=検索／`Cmd/Ctrl+Z`=Undo／`Esc`=解除。
  インライン編集中はグローバルショートカット無効。
- **Undo/Redo は最初から**。1確定＝1 Undo単位。差分（zundo diff）で履歴メモリを抑える。

### 3.2 表示パイプライン（大規模対応の中核）

4,000ノードを一度に描かないための統合点。UI非依存の純関数 `deriveVisibleGraph` /
`deriveTableRows` が「何を載せるか」を一元決定する。

```
全タスク(4,000)
  → ① フィルタ判定（matchesFilter・AND結合）
  → ② 担当＋前後の境界展開（expandBoundary・受け渡し先を文脈に含める）
  → ③ 近傍フォーカス（neighborhood・選択タスクの前後N世代）
  → ④ WBSツリー化 → ⑤ 折り畳み（集約ノード化）
  → ⑥ ソート／DFS平坦化
  → 表示（常時 数百ノードに制御）
```

- **DIM**（淡色で残す）と **ISOLATE**（抽出＝除去）の2モード。フィルタ外の受け渡し先は
  `outside`（破線・文脈）として区別。
- グラフ・テーブル・ガントは**同じ絞り込み状態を共有**する（ビュー間で結果が一貫）。

### 3.3 ナビゲーション（絞り込みの主役）

- **組込みビュー**：「自分のタスク」＝担当ISOLATE＋前後1世代（受け渡し先が一目）。「CPのみ」＝背骨抽出。
  「マイルストーン」。
- **担当＋前後（世代調節）**：フィルタ一致集合から**前 up 世代・後 down 世代**の受け渡し先を文脈表示。
  左パネルのステッパで前後それぞれ 0〜9 を調節（`expandBoundary`・多起点BFS）。
- **近傍フォーカス（`H`）**：選択タスクを起点に上流/下流を世代バッジ付きで表示。
  `highlight`（全体を残し近傍を強調）と `isolate`（近傍だけ抽出）を切替。世代マップ（起点0・上流負・下流正）。
- **検索パレット（`Cmd/Ctrl+K`）**：名前/WBS/担当で絞り込み→Enter で `revealTask`（祖先WBS展開＋選択）。
- **WBSツリーパネル**：階層を件数付きツリーで表示。ノードクリックでそのサブツリーに絞り込み。
- **保存ビュー・既定ビュー**：現在のフィルタ/表示/折り畳み/テーブル状態を名前付きで保存。★で「既定」指定
  すると**起動時に自動適用**（毎回"自分の入口"で開く）。
- **フィルタ状態バナー**：全ビュー共通。「絞り込み中／何で絞っているか／一致件数／すべて表示✕」を常時明示。
  フィルタ変更時は結果へ**滑らかに自動フィット**。

### 3.4 WBS折り畳み（スケールの心臓部）

WBSコードのプレフィックスで木を構築。折り畳むと**集約ノード**（件数・進捗平均・工種構成・CP/MSバッジ付き
カード）になり、グラフ⇄テーブル⇄ガントで完全連動する。俯瞰（既定グラフ）は集約カードを**WBSグリッド整列**
で一望できる。MiniMap は工種色＋CP色分けで全体マップを兼ねる。

### 3.5 3つのビュー

| ビュー | 役割 | 主な操作 |
|---|---|---|
| **グラフ（G）** | 依存関係の編集・理解 | ドラッグ/クリックで接続、近傍フォーカス、俯瞰 |
| **テーブル（T）** | 一覧・並べ替え・一括編集 | 仮想スクロール、多重ソート、複数行選択＋一括操作、インライン編集 |
| **ガント（Y）** | 時間軸で工程を読む | CPM由来のバー、依存矢印、バー端ドラッグで工期変更 |

- **行集合は共通**：ガント・テーブルは同じ `deriveTableRows` を使う（順序/折り畳み/フィルタ/ソートが一致）。
- **仮想化**：テーブル・ガントとも `@tanstack/react-virtual`（4,000行でも実DOM数十行）。
- **ガントのバー座標**＝`selectCpm().byTask` の es/ef（暦日オフセット×日幅）。依存矢印は表示中ペアのみ・
  控えめな線で描画（主役はバー）。
- **ガントの時間軸は表示中タスクの期間に自動フィット**：全体（数千日）でなく、可視行の min ES〜max EF に
  ズームし、日幅はペイン幅に収まる倍率を自動算出（手動 +/− と「自動」復帰あり）。絞り込むほど読みやすくなる。
- **選択は全ビュー共有**。切替時に選択対象を自動展開・スクロール（`revealTask`）。

### 3.6 依存の接続/切断（3経路）

1. **グラフのハンドルからドラッグ** — 標準の接続。
2. **つなぐモード（🔗）** — 始点クリック→終点クリックで接続、既存なら同操作で切断（トグル）。始点保持で
   連続接続。トラックパッド向けの直感操作。**接続の瞬間、エッジに通電エフェクト**（電流が流れる発光）で
   「繋がった」を強く体感させる。
3. **右パネルの検索コンボ** — 名前/WBSで検索してクリックで先行/後続を追加、×で削除。

**循環は常に自動拒否**（`canConnect`：自己ループ・重複・DAG違反を検出し、経路を添えてトースト）。

### 3.7 EPC特有の見せ方

工種は色（E青/P橙/C緑/OTHER灰）＋文字で二重に示す（色だけに頼らない）。ステータスはバッジ、進捗はミニバー、
マイルストーンは菱形、CPは赤で強調。

## 4. 技術スタックとアーキテクチャ

### 4.1 スタック

- **Vite + React 18 + TypeScript**。
- **グラフ描画：React Flow v12（`@xyflow/react`）**。4,000+ノードは表示パイプラインで数百に制御して捌く。
  `onlyRenderVisibleElements` ＋ LOD ＋ `memo`。撤退可能性のため React Flow 依存は `adapters/` に隔離。
- **状態：zustand + immer + zundo（差分Undo）**。
- **永続化：Dexie（IndexedDB）** の差分保存＋ localStorage（表示設定）。
- **レイアウト：dagre**（表示中は同期・全体は Web Worker）。
- **検証：Zod**（スキーマ）＋独自の意味検証（DAG・参照整合）。

### 4.2 レイヤー分離

```
domain/    純関数（UI非依存の唯一の真実）: 型・スキーマ・CPM・グラフ演算・表示パイプライン・MSPDI
store/     zustand ストア・メモ化セレクタ・永続化・useCpm フック
storage/   Repository 抽象 + DexieRepository（差分保存）
adapters/  React Flow 変換（撤退可能性の隔離点）
layout/    dagre（同期 + Worker）
components/ UI（1機能1ファイル・table/ gantt/ サブフォルダ）
styles/    機能別CSS（base/nodes/panels/graph-extra/table/gantt/search）
```

- **domain は React/DOM に一切依存しない**。全アルゴリズムは純関数で Vitest 対象。
- ストア更新は定義済みアクション経由のみ（直接 setState は lint で禁止）。
- CPM は `useCpm` フックに集約（tasks/deps/dataDate/calendar を購読しメモ化）。

## 6. データモデル

交換フォーマット（JSON）がストレージの真実。`schemaVersion` で前方互換を管理（optional 追加は据え置き）。

```ts
interface Task {
  id: string; name: string; wbsCode: string;         // "" 可・プレフィックスがWBS木を定義
  discipline: 'E'|'P'|'C'|'OTHER';
  isMilestone: boolean; durationDays: number;         // milestone は 0 強制
  status: 'NOT_STARTED'|'IN_PROGRESS'|'DONE'|'ON_HOLD';
  progress: number;                                   // 0-100 整数
  assignee: string;                                   // 部署名（§用語）
  constraintType: 'ASAP'|'SNET'|'FNLT'; constraintDate: string|null;
  notes: string; position: {x:number;y:number};
  rev: number; createdAt: string; updatedAt: string; updatedBy: string;  // 行版数（衝突検知の単位）
}
interface Dependency {
  id: string; predecessorId: string; successorId: string;
  type: 'FS'|'SS'|'FF'|'SF'; lagDays: number;         // 負値=リード
  rev: number; updatedAt: string; updatedBy: string;
}
interface SavedView {
  id; name; filter; displayMode; collapsedWbs;
  tableSort?; tableColumns?;                           // optional・前方互換
  createdBy; updatedAt;
}
interface Calendar { id; name; workingDays: number[]; holidays: string[]; }  // 稼働曜日（土日も可）
interface GraphDoc {
  schemaVersion; project; viewState; savedViews; calendars; tasks; dependencies;
}
```

- **導出値（CPM の ES/EF/…）はDBに焼かない**。常に `selectCpm` で計算（メモ化）。
- **行レベル `rev`/`updatedBy` は最初から持たせる**（将来の楽観ロック・複数人編集を後付け可能に）。

## 7. CPM（クリティカルパス法）

`domain/cpm.ts`・UI非依存の純関数。O(V+E)、4,000ノードで <20ms。UI全体の共有導出値
（CP強調・`criticalOnly`フィルタ・日付表示・ガント・完了日サマリがこの1つの結果を参照）。

- **依存タイプ＋ラグ**：FS/SS/FF/SF ＋ lag（負でリード）。前進計算で後続の最早開始下限、後退計算で先行の
  最遅終了上限を型別に課す。駆動依存（CPエッジ）も型対応で判定。
- **日付制約**：SNET（開始猶予下限→ES丸め）／FNLT（終了期限上限→LF丸め・期限割れは TF 負でCP化＝遅延警告）
  ／ASAP（既定）。
- **稼働カレンダー**：所要は稼働日で数え、非稼働日（休日曜日・祝日）は跨いで暦日で伸びる。**土日も稼働日に
  設定可**。全曜日稼働＋祝日なしは線形の高速パス。es/ef は暦日オフセット（ガントの線形軸を保つ）。
- **結果**：ES/EF/LS/LF・TF（=LS−ES）・isCritical（TF≤0）・各実日付。TF≤0=赤、TF≤5=橙の準クリティカル閾値。

## 8. 永続化

- **Repository 抽象**（全フェーズ共通）→ `DexieRepository`。デバウンス500msで**差分保存**（変更/削除した
  行IDだけを書く。immer の構造共有でメモリ膨張を防ぐ）。
- **複数プロジェクト**（新規/複製/切替/削除）。保存履歴。
- **表示設定**（アクティブビュー・表示列・既定ビューID・「私は誰」）は localStorage。
- **エクスポート/インポート**：JSON（`.epcgraph.json`）。取込時は Zod ＋ 意味検証を全チェック（違反は行番号
  付きエラー）。
- **起動フロー**：starter を同期表示 → Dexie から現在プロジェクトを非同期ハイドレート → 既定ビューを自動適用。
  Dexie 不可環境でも starter で動作。

## 9. MS Project 連携（MSPDI）

`domain/mspdi.ts`（DOM非依存の軽量パーサ）。ヘッダ「データ ▾」から出力/取込。

- **toMspdi**：タスク（名前/WBS/所要/マイルストーン）＋依存（タイプ↔MSPDIコード・ラグ）＋任意で
  Start/Finish（CPM 由来）。
- **fromMspdi**：要約タスク（Summary=1）除外・Duration の h/8 日換算・LinkLag 換算・XMLエスケープ往復。
  取込は空ドキュメント化→検証→ロード→全体整列。
- 今後の拡張：リソース（担当）・カレンダー・実績のマッピング。

## 10. デザインシステム

明るいライトUI（Apple/Google 級の質感）。詳細は [`design-principles.md`](./design-principles.md)。

- **トークン**（`:root`）：アクセント `#0071e3`・文字 `#1d1d1f`・背景 `#f5f5f7`・ヘアライン境界・
  多層ソフト影（sm/md/lg）・半径 10/7。半透明 backdrop-blur のツールバー。
- **コンポーネント型**：無枠の柔らかいボタン、pillチップ、iOS風セグメントコントロール（ビュー切替）、
  角丸ソフト影のドロップダウン/ポップオーバー、アクセント地の状態バナー。
- **意味のあるマイクロインタラクション**：フィルタ変更→自動フィット、新規ノード→フェードイン、
  接続→通電エフェクト、完了日変化→フラッシュ。0.12〜0.5s。装飾だけの動きは入れない。
- **アクセシビリティ**：色以外の手がかり（工種は色＋文字）、キーボード経路、フォーカスリング。

## 11. テスト戦略

- **ドメイン単体（Vitest）**：CPM は手計算フィクスチャ（依存タイプ・制約・カレンダーで ES/EF/LS/LF/TF/CP を
  明示検証）、グラフ演算（循環・トポソート・近傍・境界）、表示パイプライン（フィルタ×折り畳み×ソート×
  focus×担当＋前後）、MSPDI 往復。性能テスト（4,000で derive <30ms・CPM <20ms）。
- **E2E（Playwright）**：起動→作成→接続→リロード復元のスモーク、各ビュー、フィルタバナー、担当＋前後、
  つなぐモード＋通電、保存ビュー/既定ビュー、ガント（矢印・duration編集）、MSPDI 実ファイル往復 等。
- テストは UI 配置に依存させず、状態は露出した `window.__APP` で駆動/検証する。
- 直接 setState 禁止 lint・tsc・lint をグリーンに保つ。
